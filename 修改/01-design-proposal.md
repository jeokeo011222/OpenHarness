# 01 · 需求与方案（只出方案，不写代码）

**适用时机**：宪法通过之后。
**产出**：一页纸方案，含架构、数据模型、工具清单、分期、验收场景。**零代码**。
**为什么单独一轮**：方案定错了，后面 8 轮全白干。让它先想清楚再动手，比让它边写边想便宜得多。

## 提示词正文（整段复制）

```text
【任务】为 DSH 设计一个「数据分析」插件的能力方案。这一轮只出方案，不写任何代码（最多给接口签名和 JSON 结构）。

【产品需求】
1. 数据源三条：
   a) 导入本地 CSV / Excel 文件；
   b) 连接关系型数据库，读表或执行查询；
   c) 调应用系统的 RESTful API 取 JSON。
2. 数据要能"加载成数据集"（dataset）——后续所有分析都基于数据集，而不是基于某个文件或某次 SQL 结果。
3. 数据集要能可视化：选字段 → 出图 → 保存图表。
4. 要能 AI 交互分析解读：用自然语言提问，得到图表 + 文字解读，支持多轮追问。

【必须回答的 7 个决策】（每个给出推荐 + 一句话理由 + 备选）
1. 执行边界：分析计算放在 Host（Node/TS）里，还是旁挂一个 Python 服务？考虑：部署复杂度、依赖安装、10 万行级别的聚合够不够。
2. 存储形态：数据集落在工作区文件（NDJSON + meta.json）、还是内置 SQLite（node:sqlite）、还是外部 DuckDB？考虑：零依赖、可迁移、版本化。
3. 统一模型：三条数据源怎么收敛成同一个 Dataset？给出 Dataset / Field / Source / Chart / Analysis 的字段定义（JSON 形态）。
4. 图表渲染：自绘 SVG、还是引入 ECharts？考虑：包体积、主题 token 适配、依赖安装失败风险。
5. AI 链路：走"Agent 调工具"（用户在会话里问，Agent 取数出图给解读），还是"面板内嵌独立对话"（插件自己调模型）？分别列出要实现的东西。
6. 查询方式：让模型生成 SQL，还是生成受限的查询 DSL（dimensions / measures / filters / timeGrain）？考虑：幻觉、注入、可校验性。
7. 第一期砍掉什么：明确写出"非目标"，防止范围蔓延。

【约束提醒】
- 这是 DSH 插件：Host 侧用 ctx.tools.register 注册工具，Client 侧用右栏 tab 承载面板（ctx.sidebarRightTabs.register + sidebar.right.pane.tab）。
- 具体 API 名称先用 cordis_inspect_query 确认再写进方案；确认不了的写"待查证"。
- 零依赖优先。

【输出格式】（严格按此结构，控制在一页纸内）
1. 目标 / 非目标（各 3 条以内）
2. 架构图（ASCII，标出 Host / Client / Agent / 存储 四层的数据流）
3. 数据模型（Dataset、Field、Source、ChartSpec、AnalysisResult 的字段，JSON 形式）
4. 工具清单（表格：工具名 | 参数 | 返回 | 谁调用）
5. 面板信息架构（左中右分区、每个区域的空态/加载态/错误态）
6. 分期计划（P0 骨架 / P1 单数据源打通 / P2 三源齐全 / P3 AI 解读），每期一句"验收即完成"
7. 风险清单（至少 5 条，每条给缓解措施）
8. 验收场景（5 条，用"用户做什么 → 看到什么"描述）

不要写实现代码。不要开始建文件。
```

## 拿到方案后你要做的判断

| 决策点 | 推荐 | 什么时候该选另一边 |
|---|---|---|
| 执行边界 | 纯 Host（Node） | 已有 Python 数据栈、要做机器学习/复杂统计时，才旁挂服务 |
| 存储形态 | 工作区 NDJSON + meta.json | 数据量 > 500 万行、要频繁 join 时换 DuckDB |
| 图表 | 自绘 SVG 起步 | 需要复杂交互（缩放、刷选、地图）时上 ECharts |
| AI 链路 | Agent 调工具 | 要给"不会用聊天框"的业务人员一个纯按钮界面时，才做面板内嵌 |
| 查询方式 | 受限 DSL | 数据在库里、且必须走库的算力时，才允许"受控 SQL"（只读 + 白名单 + 限行） |

**一句话原则**：第一期所有选择都偏向「少一个依赖、少一个服务、少一个要维护的抽象」。

## 验收清单

- [ ] 7 个决策都有明确推荐，没有"都可以"
- [ ] 非目标写清楚了（比如"不做定时刷新""不做多用户共享""不做地图"）
- [ ] Dataset 模型能同时容纳 CSV 行、SQL 结果、API JSON 三种来源
- [ ] 工具清单里每个工具的返回都是结构化 JSON，不是自然语言
- [ ] 风险清单里有「依赖装不上」「大文件 OOM」「模型编数字」这三条
