# 07 · 可视化图表

**适用时机**：查询层验收通过后。
**产出**：ChartSpec 规格 + SVG 渲染 + 面板配图流程 + 聊天卡片。

---

## 提示词正文（整段复制）

```text
【任务】给 data-analysis 插件加可视化。核心是把"图"变成一份可存、可回放、可由 AI 生成的 JSON 规格（ChartSpec），渲染只是它的一个消费者。

【ChartSpec（定死后不许轻易改）】
{
  id, datasetId, name, createdAt,
  type: 'bar'|'line'|'area'|'pie'|'scatter'|'table'|'kpi',
  encoding: {
    x?: { field, type: 'dimension'|'time', timeGrain? },
    y?: [{ field, agg, alias? }],           // 多指标叠加
    series?: { field },                      // 分组/多系列
    size?: { field },                        // 散点气泡
    label?: { field }
  },
  filters?: [...],                           // 与 DSL 同构
  options: { stacked?, horizontal?, showLegend?, showValues?, yAxisTitle?, xAxisTitle?, colorScheme? },
  queryHash?                                  // 生成时的查询哈希，用于判断是否过期
}

【渲染（Client）】
- 第一期自绘 SVG，不引图表库：bar（含横向、分组、堆叠）、line（含面积）、pie（含环图）、scatter、table、kpi 卡片各一个组件。
- 尺寸自适应容器：用 ResizeObserver 拿宽度，高度按 16:9 或固定 320px，窄容器（< 360px）自动切横向条形图。
- 坐标轴：Y 轴 4~5 个刻度，数值用 1.2k / 3.4万 这种紧凑格式；X 轴类目超过 20 个时抽稀标签（每 N 个显示一个）。
- 交互：hover 出 tooltip（跟随鼠标，靠近右边缘时翻转）；图例点击切换系列显隐；点击柱子触发下钻（把该维度值作为 filter 追加到当前查询）。
- 空态：无数据时显示"当前筛选条件下没有数据"+ 一个"清除筛选"按钮，不要画一个空坐标系。
- 加载态：骨架屏，不要用转圈遮住整个面板。
- 错误态：显示错误原因 + 重试按钮。
- 颜色：只从主题 token 派生的调色板取值（先 cordis_inspect_query 查 Theme），深浅色都要能看；不要硬编码 #5470c6 这种默认蓝。

【图表推荐规则（供"自动出图"用）】
- 1 个时间维度 + ≥1 个数值 → line
- 1 个类目维度 + 1 个数值，类目 ≤ 12 → bar；> 12 → 横向 bar 或取 Top N
- 1 个类目维度 + 1 个数值，且是占比语义 → pie（类目 > 6 时改堆叠条形）
- 2 个数值 → scatter
- 0 维度 + 1 个数值 → kpi
- 明细（维度 > 2 或无数值）→ table
这些规则写成纯函数 suggestChart(schema, queryResult)，不要散落在组件里。

【面板流程】
1. 选数据集 → 左侧字段列表（可拖拽或点选）
2. 拖/选字段到「维度」「指标」两个槽；指标可多选并选聚合方式
3. 实时预览图（改一个配置就重查一次；防抖 300ms）
4. "保存图表"→ 存到 <workspace>/.analysis/charts/<id>.json，列表里能再次打开
5. 图表面板顶部有：图表类型切换、筛选器、导出 PNG（用 SVG → canvas 转换，前端做）

【聊天卡片】
- 用 tool.call.toolview slot，key 用工具名，注册一个渲染器：把 ChartSpec 画成 320px 高的缩略图 + 标题 + 一句"在面板中打开"的按钮。
- 缩略图和面板用同一个渲染组件，不要写两套。
- 工具返回给模型的不是图片，是 { chartId, type, summary: "按月的合同金额，2024-01 至 2024-12，共 12 个点，峰值在 2024-06（¥1.2M）" }。

【验收】把下面每种情况的截图/描述给我（没有浏览器控制就说明未验证）：
1) 同一份数据切换 bar / line / pie，都能正常渲染
2) 类目 100 个时 X 轴标签不重叠
3) 含负值的数据，Y 轴有 0 轴线，柱子向下画
4) 全部为 null 的指标列 → 空态而不是崩
5) 窄到 320px 时横向条形图生效
6) 深色模式下文字/网格线对比度足够（用 token 而不是写死颜色）
7) 保存图表后刷新页面还能打开
```

## 关键点说明

- **先有 ChartSpec 再谈渲染**。直接写"画个柱状图组件"会导致：AI 生成的图存不下来、面板图和聊天图两套实现、改主题要改八处。
- **自绘 SVG 起步**不是保守，是省掉"ECharts 装不上 / 打包进 bundle 后体积 1MB / 主题 token 对不上"这三个坑。真需要复杂交互时再换，ChartSpec 不变，换渲染器不影响数据。
- **抽稀和翻转**这类细节决定了可用性。100 个类目的柱状图默认渲染出来就是一团黑，用户第一眼就判死刑。
- **颜色从 token 派生**：深浅色切换是最容易被忽略的验收项，也是"看起来不像宿主应用"的主因。

## 验收清单

- [ ] ChartSpec 能序列化、能存盘、能从文件恢复
- [ ] 同一份 spec 在面板和聊天卡片里渲染结果一致
- [ ] 空 / 单点 / 负值 / 全 null / 100 类目 五种边界都不崩
- [ ] 窄容器、深色模式、超长类目名 三种布局都没溢出
- [ ] 点击柱子能下钻（筛选条件真的追加了）
- [ ] 导出的 PNG 不是空白（SVG 转 canvas 时字体和样式丢失是常见问题）

## 常见翻车点

- 把 SVG 当 React 组件写，但数据更新时用 key 复用旧节点，图不刷新。
- tooltip 用 fixed 定位但不处理滚动，页面一滚就飘走。
- 饼图把 20 个类目全画出来，标签互相压。
- 导出 PNG 时用了外部字体，跨机器打开是方框。
