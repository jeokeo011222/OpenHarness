# 09 · 验收、安全与收尾

**适用时机**：功能"看起来能用了"之后。
**产出**：一份可信的交付报告 + 修复清单。**这一轮不写新功能。**

## 提示词正文（整段复制）

```text
【任务】对 data-analysis 插件做一次完整验收审计。这一轮不写新功能，只找问题、修 P0、出一份交付报告。

【A. 功能验收（8 条，逐条跑，逐条给证据）】
A1 文件导入：中文表头 CSV → 数据集 → 图表，全链路。
A2 文件导入：10 万行 CSV → 记录耗时与内存峰值（给数字，不许写"很快"）。
A3 数据库：SQLite 连接 → 探测表 → 导入 → 图表。
A4 API：mock server 分页 → 导入 → 图表。
A5 查询：月度聚合的数字与手算一致（贴出两个数字）。
A6 图表：保存 → 刷新页面 → 重新打开，spec 完整恢复。
A7 AI：问"按月金额趋势"，产出图 + 四段解读，每个数字可溯源。
A8 多轮：追问"换成按区域"，继承上一轮筛选条件。

【B. 安全自查（每条给"是/否 + 证据"）】
B1 路径穿越：dataset_import_file 传 ../../etc/passwd / C:\Windows\win.ini → 被拒。
B2 SSRF：api_request 指向内网地址（127.0.0.1、10.x、169.254.169.254）且不在白名单 → 被拒；重定向到外部 → 被拒。
B3 SQL：db_query 传 "select 1; drop table t"、"/*x*/delete from t" → 被拒。
B4 表达式注入：计算字段传 "1; process.exit()"、"require('fs')" → 被拒。
B5 凭据：搜索所有工具返回值、日志、错误信息、meta.json，确认没有明文密码/token。
B6 XSS：让数据里出现 <img src=x onerror=alert(1)>，确认图表标签和表格单元格都是转义文本。
B7 资源：单次导入 500MB 文件、单次查询返回 100 万行 → 都被上限拦截，进程不崩。
B8 越权：插件写的所有文件都在 <workspace>/.analysis/ 下，没有越界写 $DSH_HOME 或仓库目录。

【C. 工程质量】
C1 所有 DSH API 调用都是 cordis_inspect_query 确认过的，没有"凭记忆"的调用（列出你查证过的服务/slot 清单）。
C2 样式里没有硬编码颜色（grep # 开头的十六进制，除 icon 外应为 0 处）。
C3 所有面向用户的字符串都在 locale 里，zh/en 键集合一致（写个脚本比对）。
C4 没有 iframe、没有 CDN、没有 document.body.appendChild、没有 import @deepseek-ai/dsh-client-*。
C5 卸载插件后：tab 消失、工具消失、没有残留的定时器和监听（在 apply 里返回的 cleanup 是否真的生效）。
C6 重新安装/热更新后功能正常（不是只有首次安装能用）。

【D. 性能基线（给数字）】
- 冷启动打开面板到首屏可交互：____ ms
- 10 万行导入：____ s
- 10 万行按维度聚合：____ ms
- 一次完整 AI 问答（profile + query + chart）：____ s

【E. 交付报告（按此结构输出）】
1. 能力清单：现在能做什么、不能做什么（各 5 条以内）
2. 验收结果表：A1~A8 / B1~B8 逐条 ✅❌，❌ 的写清现象
3. 已知问题：按 P0（阻断）/P1（影响体验）/P2（可延后）分级，每条给修复建议
4. 未验证项：明确列出（例如"深色模式仅在代码层确认，未在真实页面截图核对"）
5. 使用说明：怎么装、怎么开面板、三条数据源各怎么配、AI 怎么问
6. 运维提示：数据存在哪、怎么清理、升级插件会不会丢数据

【约束】
- 发现 P0 问题就地修掉，修完重跑对应验收项；P1/P2 只记录不修。
- 不许为了让验收通过而放宽安全规则（比如把白名单改成 *）。
- 不许用 mock 数据冒充真实链路；没有浏览器控制就如实标注。
```

## 关键点说明

- **A 组要有数字**。「很快」「正常」这类词在验收里等于没说，10 万行 40 秒和 4 秒是两个产品。
- **B 组是这类功能真正的风险面**：它同时具备"读本地文件""发起 HTTP""执行 SQL""求值表达式"四种能力，任何一种没锁死都是事故。
- **B5 要真的去 grep**，而不是"我设计上没打印密码"。工具返回值、异常堆栈、meta.json 三个地方都会泄漏。
- **C5 卸载清理**最容易被忽略：注册了定时器但没在 cleanup 里清，插件一禁用就每秒钟报错。
- **E 组的"未验证项"** 是给用户看的诚实度指标。写"全部验证通过"的报告，通常意味着它没认真验。

## 常见翻车点

- 为了让 A7 通过，把"解读"写成模板填空，数字对不上也照发 —— 抽查两个数字。
- 安全项"设计了但没生效"（比如白名单写在配置里，代码里根本没读）。
- 交付报告里混入了上一轮的旧结论（没重跑就复制粘贴）。
