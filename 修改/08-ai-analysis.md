# 08 · AI 交互分析

**适用时机**：图表能出图之后。
**产出**：Agent 驱动的分析链路（系统提示词 + 工具编排 + 解读规范），可选的面板内嵌对话。

---

## 提示词正文（整段复制）

```text
【任务】让 Agent 能基于数据集做交互式分析：用户用自然语言提问，Agent 选工具取数、出图、给解读，并支持多轮追问。

【总体链路（第一期只做这条，不要做面板内嵌对话）】
用户提问 → Agent 读「数据集目录」→ 调 dataset_profile 看数据长什么样 → 调 dataset_query 取聚合结果 → 调 chart_create 出图 → 用固定结构输出解读。
三个关键点：① 模型不读原始行；② 每个数字都来自工具返回；③ 图表用工具产出而不是让模型描述。

【系统提示词（用 ctx.systemPrompt.section 注入，控制在 400 字以内）】
内容要点：
- 你有一个数据分析面板，可用工具：dataset_list / dataset_profile / dataset_query / chart_create / dataset_import_file / db_* / api_*。
- 分析前先 dataset_profile，不要凭空假设字段名和口径。
- 取数一律用 dataset_query 的 DSL，不要要求用户写 SQL。
- 一次只回答一个问题；需要多步时先说要做什么，再逐步调用。
- 数字只用工具返回值；工具没返回的不要估算。样本量 < 30 或空值率 > 30% 时必须提示"结论可靠性有限"。
- 出图后必须给文字解读，格式见下。

【解读格式（硬性，四段，总长 ≤ 300 字）】
1. 结论：一句话，带主数字（例："2024 年合同金额同比下降 18%，主要来自 Q3"）
2. 证据：2~3 条，每条都是"维度 + 数字"，标注口径（时间范围、筛选条件、样本量）
3. 异常与局限：数据缺失、口径变化、样本过小，有就说，没有写"未发现明显异常"
4. 建议下一步：最多 2 条，且必须是"能在面板里点出来的操作"（例："按区域下钻看 Q3 的构成"）

【工具设计要求】
- dataset_profile 的返回要控制在 2KB 内（列多时只返回前 20 列的统计 + 说明"还有 N 列"）。
- dataset_query 返回给模型的是 rows（最多 50 行）+ 一个 summary 字符串（行数、时间范围、极值）。超过 50 行时模型只看到 summary，完整数据进图表。
- chart_create({ datasetId, spec | auto: true, title }) → 返回 { chartId, spec, summary }。auto: true 时用上一轮 suggestChart 规则自动选图。
- 所有工具的错误信息要"可行动"：不要说 "query failed"，要说 "字段 'amount' 不存在，可用字段：金额、数量、日期"。

【防幻觉（逐条落实）】
1. 工具返回里没有的数字，模型不得出现在回答里。提示词里明确写这条。
2. 时间范围、筛选条件、样本量必须在证据段里显式出现，让用户能核对。
3. 用户问"能不能预测/为什么"时：先说清"这是相关不是因果""当前数据不支持预测"，再给可做的替代分析。
4. 工具报错时，把错误翻译成人话 + 给一个可行替代，不要假装分析成功。
5. 空结果时明确说"该条件下没有数据"，不要编一个"0"当作结论。

【多轮】
- 会话里记住当前 datasetId；用户说"再看按月"时不需要重述数据集。
- 追问默认继承上一轮的 filters 和 timeGrain，除非用户明确改。
- 用户说"这个图"时，指最近一次 chart_create 的结果。

【可选（第二期，先不做）：面板内嵌对话】
如果后续要做：复用 DSH 的 LLM 服务（先 cordis_inspect_query 查 llm 相关 Service 的方法签名），不要自己读 API Key、不要自己实现流式协议；上下文只放 profile + 最近 3 轮问答，绝不把原始行塞进 prompt。

【验收】用一份合同/销售类的样例数据，让我实际问这 6 个问题，把每轮的工具调用链和回答贴给我：
1) "这个数据集里有什么" → 应调 profile，概括字段和时间范围
2) "按月看金额趋势" → 应调 query（timeGrain=month）+ chart_create，给四段解读
3) "为什么 6 月掉了" → 应下钻维度（区域/客户/产品），而不是重复画同一张图
4) "预测下个季度" → 应说明数据不支持预测，并给出可做的替代分析
5) "把区域换成客户" → 应继承上一轮筛选，只换维度
6) "随便编一个数给我" → 应拒绝，并说明数字必须来自数据
另外故意让工具报错一次（查一个不存在的字段），确认回答是"字段不存在 + 可用字段列表"，而不是编造。
```

---

## 关键点说明

- **为什么不第一期就做面板内嵌对话**：Agent 已经在会话里，工具、审批、流式、上下文、成本全都是现成的。再嵌一套，等于把这些问题重新解一遍，而且用户会有两个"AI 入口"，体验分裂。
- **四段式解读**是这一轮最重要的产出。没有固定结构，模型会写成一篇散文，用户看不出哪个数字是结论、哪个是推测。
- **"证据段必须写口径"** 直接决定了这个功能可不可信。业务方第一反应永远是"这个数怎么算的"。
- **工具错误要可行动**：模型看到 "字段不存在 + 可用字段" 会自己纠正；看到 "query failed" 只会重试或编造。

## 验收清单

- [ ] profile → query → chart → 解读 的链路能一次走完，不需要用户催
- [ ] 回答里每个数字都能在工具返回里找到
- [ ] 证据段有明确的时间范围 / 筛选条件 / 样本量
- [ ] "预测""为什么" 这类问题有诚实的边界说明，不是硬答
- [ ] 追问能继承上下文，不用重复描述数据集
- [ ] 工具报错时给出的建议是可执行的

## 常见翻车点

- 系统提示词写了 2000 字，模型开始忽略后半段 —— 压到 400 字以内，细节靠工具描述承载。
- 把 query 的全部结果塞进上下文，几轮之后就开始"忘记"最早的约束。
- 解读里出现"显著提升""大幅下降"却没有百分比 —— 要求带数字。
- 模型自己画 ASCII 图或描述图表，而不是调 chart_create —— 在提示词里明确"不要用文字描述图表"。
