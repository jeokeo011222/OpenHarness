# 03 · 数据源① 文件导入（CSV / Excel）

**适用时机**：骨架验收通过后。
**产出**：`dataset_import_file` 工具 + 面板里的导入流程 + 落盘的数据集。

---

## 提示词正文（整段复制）

```text
【任务】给 data-analysis 插件加第一个真实数据源：本地文件导入（CSV / TSV / Excel）。目标是把一个"脏文件"变成一份可信的数据集。

【Host 侧：新增工具 dataset_import_file】
参数（用 ctx.tools.register 的原始 JSON Schema 写，别引 defineTool，保持零依赖）：
- path: string（必填）——工作区内的文件路径，必须校验解析后的绝对路径落在当前会话工作区内，拒绝 ../ 和工作区外路径
- name?: string——数据集显示名，缺省用文件名（去扩展名）
- sheet?: string——Excel 的工作表名；缺省取第一个非空表
- delimiter?: string——仅 CSV，缺省自动嗅探 ，; \t |
- headerRow?: integer——表头所在行，缺省 1
- encoding?: string——缺省 utf-8
- limitRows?: integer——调试用，只导前 N 行

返回（结构化 JSON，给模型看的）：
{ datasetId, name, rowCount, columnCount, columns: [{ name, type, nullRate, distinct, sample: [...] }], warnings: [...], preview: 前 5 行 }

【解析要求，逐条实现】
1. 编码：检测 BOM（UTF-8 BOM 要剥掉）。遇到非 UTF-8（GBK/GB18030）不要瞎猜：报一个明确错误，提示"请另存为 UTF-8"，并在 warnings 里给出检测到的字节特征。第一期不做编码转换。
2. CSV：必须正确处理①引号内的逗号、②引号内的换行、③转义的双引号 ""、④CRLF/LF 混用、⑤行尾空列。不许用 split(',')。
3. 分隔符嗅探：取前 20 行，对 ，; \t | 分别统计"每行字段数方差"，取方差最小且字段数 > 1 的。
4. 表头：去首尾空白；空表头补成 column_1..n；重名表头补后缀 _2；表头行以下全空的行要跳过。
5. 类型推断（每列独立判断，样本取前 500 行，全列复核）：
   - integer：全是可解析整数（允许千分位逗号？不允许——千分位一律当字符串，避免把"1,234"和"1"混为一谈）
   - number：全是可解析小数，允许负号、科学计数法
   - boolean：全是 true/false/是/否/Y/N（大小写不敏感）
   - date / datetime：常见格式（YYYY-MM-DD、YYYY/MM/DD、YYYY-MM-DD HH:mm:ss、ISO8601）
   - string：兜底
   - 前导零的列（如 00123、邮编、工号）强制 string，不要转成数字
   - 一列里 90% 以上是同类型才认定该类型，否则 string，并在 warnings 里记一条"第 X 列类型混杂"
6. 空值：""、"NULL"、"null"、"N/A"、"-" 统一成 null，但只在整列没有真实字符串值时才这么干（避免把产品名 "N/A" 吃掉）。
7. 数值列要同时算出：min / max / mean / p50 / p95（用于后续 AI 数据画像）。

【落盘】
- 目录：<workspace>/.analysis/datasets/<datasetId>/
- data.ndjson：一行一条记录，字段名用列名
- meta.json：{ id, name, source: { kind: 'file', path, format, sheet, sizeBytes, mtime }, schema: [...], rowCount, createdAt, contentHash, version }
- contentHash 用文件内容的哈希：同 hash 重复导入时不要新建，直接返回已有 datasetId，并在 warnings 里说明"已存在相同数据集"。
- 写入用流式，不要一次性把整个文件读进内存；超过 200MB 或 100 万行时，默认拒绝并返回明确错误（附当前大小/行数），除非参数里显式 force。

【Client 侧】
- 面板顶部加「导入文件」入口，点击展开一个小表单：路径输入框 + 可选数据集名 + 格式自动识别提示。
- 导入中显示进行中状态；成功后刷新左侧数据集列表，并自动选中新数据集。
- 失败时把后端返回的错误原文显示出来（不要吞成"导入失败"）。

【不要做的事】
- 不做文件上传（第一期只认工作区路径）；用户把文件拖进对话时，Agent 会拿到路径，走同一个工具。
- 不做 Excel 公式计算，读缓存值即可。
- 不做多表合并。

【验收】用你造的 5 个 fixture 跑通并把结果贴给我：
1) 标准 UTF-8 CSV，中文表头
2) 带引号内逗号和引号内换行的 CSV
3) 空列 + 重复列名 + 类型混杂列
4) 10 万行的 CSV（报耗时）
5) 一个 .xlsx（多 sheet，日期列）
另外演示：同一文件导入两次，第二条返回的是同一个 datasetId。
```

---

## 关键点说明

- **限制在工作区内**是安全底线，不是洁癖。否则一句 `path: C:\Windows\...` 就能把宿主文件读进数据集。
- **前导零强制字符串**这一条最容易被忽略，也最容易在真实业务里出事（工号 00123 变成 123）。
- **contentHash 幂等**是为了后面「换了个文件但内容一样」时不产生重复数据集，否则面板会被副本淹没。
- **流式写盘**决定了你这版能不能吃下 10 万行以上，一次性 `readFileSync` 会在 50 万行时直接 OOM。

## 验收清单

- [ ] 中文表头不乱码，列名首尾空格被清掉
- [ ] 引号内逗号 / 换行解析正确（对比 Excel 打开的结果）
- [ ] 工号、邮编这类前导零列是字符串
- [ ] 重复列名自动加了后缀，没有互相覆盖
- [ ] 10 万行导入有明确的耗时数字，内存没有爆
- [ ] 同一文件导两次返回同一 datasetId
- [ ] GBK 文件报的是可读的中文错误，不是乱码堆栈
- [ ] 路径穿越（../../）被拒绝

## 常见翻车点

- 用 `split(',')` 解析 CSV —— 第一段带引号的文本就崩。
- 类型推断只看前 10 行 —— 第 500 行出现一个 "暂无" 就把整列变字符串（这其实是"正确"的，但要保证整列复核后能纠正回来）。
- 日期列被当成字符串，后面按时间聚合时报错。
- 写盘用 `JSON.stringify` 整体序列化 —— 10 万行直接几个 G 的字符串。
